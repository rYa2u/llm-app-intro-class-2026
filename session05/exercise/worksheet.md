## コードの説明
- search_keyword()で単語ごとの一致件数を数え、仮のraiseを削除する。
- 自分が変更した行の意味：forで検索語を1つずつ取り出し、ifで資料名・見出し・本文を連結した文字列に含まれるか調べる。一致した検索語ごとにscoreを1増やす。同じ語が資料中に何度登場しても、その検索語の加点は1回。未実装を示すraiseを削除した。
- 点数と件数：0点の資料は除外する。results.sort(key=get_score, reverse=True)で点数の高い順に並べ、results[:top_k]で最大件数を制限する。同点では元の資料ID順を維持する。
- データが通る場所：画面の質問・検索語・上位件数 → POST /api/ask → main.pyのask() → knowledge.pyのsearch_keyword()でDBの断片を検索 → llm.pyのask_with_context()とbuild_context()で資料を入力に追加 → 回答と参照資料を画面へ返す。ask()内のsearch_keyword()が検索、ask_with_context()が生成を担当する。
- 検索語の作り方：この教材では質問と検索語を別々に入力する。search_text.lower().split()で英字を小文字にし、空白で分割する。講師の画面にあるJanomeによる自動抽出は、この版には実装されていない。

## 確認問題への回答
1. モデル自体を学習し直していない。関連資料を検索し、その本文を質問と一緒に入力へ追加して回答させる。
2. 必ず正確になるわけではない。必要な根拠が増える場合もあるが、無関係な資料や矛盾した情報が増える場合もある。今回の上位5件は上位3件と同じだった。
3. 呼ぶ必要はない。この教材では0件ならLLMを呼ばず、参照できる資料がないと返す。
4. 資料と表記や言い回しが違う質問。例えば「データが消えない仕組み」と「永続化」は意味が近くても文字列が一致せず、今回も前者の検索語では0件だった。

## 失敗と改善
- 失敗した操作・入力：検索語「データが消えない仕組み」で必要な資料が見つからなかった。また「SQLite 保存」ではAPIキーの保管についての資料も選ばれた。
- 原因の予想：検索は意味を理解せず、各検索語が文字列として含まれるかだけを調べるため。一般的な「保存」は別の話題にも一致する。
- 試した変更：検索語を「永続化」にすると必要な資料を取得できた。上位件数1・3・5を比較し、件数を増やしても常に有用な資料だけが増えるわけではないことを確認した。
- 誤答時の調べ方：参照資料に必要な根拠がなければ検索語・分割・件数を調べる。根拠があるのに誤答する場合は、生成の指示・文脈・出力を調べる。
- まだ確かめていないこと：実際のAPIによる回答精度、引用IDと回答内容の対応、上位件数による入力トークンの変化。今回の結果から生成の品質は判断できない。
